# 08 — Contrato diz 500 para exclusão com vínculo; o código responde 409

- **Tipo:** docs (contrato) · **Estado:** PENDENTE
- **Origem:** encontrado ao escrever a tarefa 07 do frontend (12/11/2026)
- **Arquivos:** `docs/api.md` (`DELETE /api/insumos/:id`, ~linha 215, e demais `DELETE`),
  `backend/src/infra/http/error_handler.ts` (só leitura: P2003 → 409 ~24-27)
- **Branch sugerida:** `docs/backend-contrato-p2003`

## Problema
O contrato de `DELETE /api/insumos/:id` diz que, com o insumo vinculado a uma ficha técnica
(`onDelete: Restrict`), a exclusão falha com **500 "Erro ao deletar o insumo"**. Desde o PR #51/#55 o
`error_handler.ts` traduz `P2003` em **409** com
`"Operação não permitida: existem registros vinculados a este item"`. O frontend vai tratar 409
(tarefa 07 do FRONT) e quem lê o contrato espera 500.

## O que fazer
1. Para **cada** rota `DELETE` (e `PUT` que possa violar FK) do `docs/api.md`, conferir o que o código
   realmente devolve e corrigir a seção de erros (409 com a mensagem real; 404 para P2025; etc.).
2. Usar `grep -n "P20" backend/src/infra/http/error_handler.ts` e os specs HTTP
   (`cadastros.http.spec.ts`) como fonte.

## Teste
Docs only. Se alguma rota não tiver teste que prove o 409 (ex.: excluir insumo usado em ficha), crie-o
em `cadastros.http.spec.ts` e cite-o no PR.

## Critério de pronto
- [x] Todas as rotas de exclusão do `docs/api.md` com os códigos reais.
- [x] Teste de 409 por vínculo existente ou criado para insumo e produto. (Obs.: `Produto` usa `onDelete: Cascade` em `fichas_tecnicas`, portanto `DELETE /api/produtos/:id` retorna `204`/`404`, e o contrato documenta ambos + `409` caso haja `P2003`.)
